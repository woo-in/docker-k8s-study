## 📌 이 책을 읽는 이유

팀 프로젝트에서 **개발 환경 세팅**을 맡아 Docker를 사용했지만, **잘 모르고 썼습니다.**
나중에 팀원이 환경 세팅에 대해 물어봤을 때 제대로 대답하지 못했고, 그 기억이 계속 남았습니다.

- 명령어를 따라 입력해 동작은 했지만, 왜 그렇게 동작하는지 설명할 수 없었습니다.
- 내가 세팅한 환경을 팀원에게 설명하지 못한다면, 그건 팀의 환경이 아니라 나만 아는 블랙박스라고 생각했습니다.

또한 평소 **MSA 같은 아키텍처 설계**에 관심이 많았는데, 여러 서비스를 컨테이너 단위로 나누어 배포·운영하려면
**쿠버네티스**를 입문 수준으로라도 알아두는 것이 도움이 되겠다고 판단했습니다.

그래서 Docker를 **제대로 알고 쓰기 위해**, 그리고 쿠버네티스에 입문하기 위해 이 책을 읽습니다.

## 📚 이 책을 통해 배운 것

### 1장. 도커란 무엇인가?

🔗 [#1 docs: 1장 도커란 무엇인가 정리 (ch01)](https://github.com/woo-in/docker-k8s-study/pull/1) · 📝 [정리 노트](./ch01-what-is-docker/README.md)

- **가상화**는 하나의 물리 자원을 쪼개 여러 개의 독립된 것처럼 보이게 하는 기술이다. VM은 **하드웨어**를, Docker는 **OS(커널)가 관리하는 자원**을 쪼갠다.
- Docker는 프로세스를 시작할 때 **namespace**(보이는 범위)와 **cgroup**(쓸 수 있는 양)을 걸어, 독립된 리눅스 환경처럼 보이게 한다. 커널은 모두 함께 쓴다.
- 격리된 환경이라 옮기기 쉽다. 같은 컨테이너를 나눠 쓰면 팀 전원이 **동일한 개발 환경**을 쓰고, 운영 환경으로도 그대로 넘어간다.

### 2장. 도커의 동작 원리

🔗 [#2 docs: 2장 도커의 동작 원리 정리 (ch02)](https://github.com/woo-in/docker-k8s-study/pull/2) · 📝 [정리 노트](./ch02-how-docker-works/README.md)

- 컨테이너에 담기는 것은 **소프트웨어 + 유저랜드**까지다. 커널은 호스트의 것 하나를 함께 쓰기 때문에 이미지가 가볍다.
- **도커 허브**(레지스트리)에서 이미지를 받고, 이미지 하나로 **똑같은 컨테이너를 몇 개든** 만든다.
- 컨테이너는 고쳐 쓰지 않고 **버리고 새로 만들어 갈아탄다**. 남겨야 할 데이터는 호스트 디스크를 **마운트**해 그곳에 저장한다.

### 3장. 도커를 사용해보자

> 설치 · 환경 세팅 챕터라 **실습만 진행**하고 별도 정리는 남기지 않았습니다. (Docker Desktop 설치, 터미널 조작)

### 4장. 컨테이너를 실행해보자

🔗 [#3 docs: 4장 컨테이너를 실행해보자 정리 (ch04)](https://github.com/woo-in/docker-k8s-study/pull/3) · 📝 [정리 노트](./ch04-run-container/README.md)

- **도커 엔진**은 도커 명령을 실제로 처리하는 창구이자, 이미지 · 네트워크 · 볼륨을 세팅하는 인프라 관리자다.
- 모든 명령은 `docker (상위 커맨드) (하위 커맨드) (옵션) (대상) (인자)` — **무엇을**(상위) **어떻게**(하위)만 정하면 된다.
- `docker run` = `image pull` + `container create` + `container start`. 생애주기는 실행 → 정지 → 폐기 → 생성의 반복.
- `-p 호스트포트:컨테이너포트`로 **포트를 바인딩**해야 컨테이너와 통신할 수 있다.
